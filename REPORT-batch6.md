## Что сделано

### «Тяжёлый список»
- **Вкладки чатов** — открытые чаты показываются таб-полосой над лентой (точка = идёт генерация), `Ctrl+Tab` / `Ctrl+Shift+Tab` переключают, закрытие активной вкладки переносит на соседнюю. До ~8 вкладок, только в рамках сессии.
- **Quick-chat мини-окно** — глобальный хоткей `Ctrl+Shift+Q` (переназначается в настройках): маленькое always-on-top окно по центру активного монитора, отвечает через провайдера/модель последнего чата. Esc или потеря фокуса прячут. Рендерится тем же бандлом через `#quick`-хэш.
- **Compare-режим** — кнопка ⇄ в тулбаре: последний ход диалога переигрывается на втором провайдере/модели (один нестриминговый мини-запрос), ответ текущего чата берётся из БД без лишнего вызова. Два ответа рядом в модалке.
- **Mermaid** — ```` ```mermaid ```` блоки рендерятся в диаграммы: ленивый импорт (mermaid вынесен в отдельный чанк ~666 КБ, в основной бандл не попал), `securityLevel: 'strict'`, тема берётся из приложения, сломанная диаграмма остаётся код-блоком.
- **RAG-lite (документы к чату)** — кнопка-книга в тулбаре: до 8 файлов (txt/md/pdf/код, ≤20 МБ, текст до 200k символов; PDF через `pdf-parse`). На каждое сообщение чанки по 1.8k ранжируются по ключевым словам запроса, топ-6 (бюджет ~8k) подмешиваются в системный промпт. Без векторной БД.
- **MCP** — минимальный stdio-клиент (`electron/mcp.ts`): Content-Length фрейминг + fallback на построчный JSON, таймауты 15 с на коннект / 60 с на вызов, кэш сессий. До 5 серверов в Settings → Personas (например `npx -y @modelcontextprotocol/server-filesystem .`). Инструменты доступны модели как `mcp__<сервер>__<инструмент>` (в UI — карточки `mcp: …`). Упавший сервер пропускается с заметкой в reasoning, чат не ломается.
- **Субагенты** — инструмент `spawn_subagent`: вложенный цикл до 3 раундов, только read-only инструменты (чтение/поиск/git-статус/sql), без диалогов подтверждения, на том же провайдере/модели; возвращает компактный отчёт в основной контекст.
- **Автообновления** — `electron-updater` (lazy-require, только в установленной сборке): проверка при старте, автозагрузка, диалог «перезапустить»; в Settings → Data кнопки «Check for updates» / «Restart & install». Для приватного репозитория проверке нужен `GH_TOKEN` в окружении (иначе — честное «нет информации об обновлении»).

### 5 самочинных идей
- **Actionable-тосты** — после изменения файла моделью всплывает тост с кнопкой «Roll back» (9 секунд, использует снапшот из batch 5).
- **Zip-экспорт чата** — `conversation.md` + `messages.json` + файлы вложений, упаковка через `Compress-Archive` (Settings → Data).
- **Командная палитра** (`Ctrl+P`) — статичные команды (новый чат, настройки, сайдбар, focus, compare, summarize, zip-экспорт) + нечёткий поиск по чатам, Enter выполняет первый пункт.
- **Карточки инструментов** — в стриминговом пузыре видно каждый вызов: имя, подсказка-аргумент, статус (running/✓/declined/failed). События идут по каналу `chat:tool`.
- **@file автодополнение** — в композере `@src/ut…` открывает меню путей из workspace (стрелки/Tab/Enter/Esc), до 50 совпадений через `chats:list-workspace-files`.

### Дешёвые остатки
- **Рейтинги ответов** — 👍/👎 на ответах ассистента (колонка `messages.rating`, повторный клик снимает оценку).
- **watch_files** — снапшот mtime файлов workspace по чату; модель получает список «что изменилось на диске вне приложения с прошлого ответа» и перечитывает перед правками.
- **`sql_query`** — read-only SELECT по `.csv` (загружается в память как таблица `data`) и `.sqlite`/`.db` файлам workspace (sql.js, лимиты: 100 МБ файл, 50 строк результата).
