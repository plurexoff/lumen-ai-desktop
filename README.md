# Lumen AI Desktop

Local-first multi-provider AI chat workspace for Windows. Electron + React + TypeScript, with privileged main-process API calls, encrypted credentials and persistent SQLite history.

## Requirements
- Windows 10/11 x64
- Node.js 20+ and npm
- An API key from a supported provider

## Run locally
```sh
npm install
npm run dev
```
> A `predev` hook compiles `electron/*.ts` → `dist-electron/` before every dev run, so a fresh clone works out of the box. Re-run `npm run build:electron` (or restart `dev`) after editing anything under `electron/`. Renderer edits under `src/` hot-reload via Vite without a rebuild.

## Build and package
```sh
npm run typecheck
npm run lint        # eslint flat config, TS + react-hooks rules
npm test
npm run build       # = build:renderer (vite) + build:electron (tsc)
npm run dist:win    # = build + electron-builder --win nsis
```
The NSIS installer is written to `release/`. The window/taskbar/installer icon is `build/icon.ico` (electron-builder's default `buildResources` directory), so it is picked up with no extra config. The authoritative packaging config is `package.json → build` (electron-builder ignores `electron-builder.yml` whenever `package.json` has a `build` section, so the misleading duplicate was removed).

## Providers
OpenAI, Anthropic, Google Gemini, OpenRouter, Groq, DeepSeek and Mistral are preconfigured. Add a key in Settings → Providers. Credentials are encrypted using Electron `safeStorage` (Windows DPAPI); the app refuses to store a key when system encryption is unavailable. Custom endpoints support OpenAI-compatible `/models` and `/chat/completions` APIs. Remote endpoints must use HTTPS; `http://localhost` / `http://127.0.0.1` are allowed so local servers (Ollama, LM Studio) work out of the box. The Gemini API key is sent in a request header, never in the URL.

## Data and privacy
Chat records and preferences are stored in `lumen.sqlite` under Electron's user-data directory. Provider secrets are encrypted blobs in the local database. Network requests originate in Electron main; the renderer receives stream chunks and provider metadata only. Internet access and a valid provider key are required for live responses.

## Screens
- **Workspace:** conversation sidebar with **pinned chats**, **folders** (create/rename/delete, drag-and-drop; deleting a folder never deletes its chats), **archived chats** (hidden but kept, expandable section at the bottom), per-chat **tags** (comma-separated editor; chips double as search filters), title search plus full-text search with **filters** (model, role, folder, tag, date range) — clicking a message hit **opens the chat and jumps straight to the matched message** — an **unread dot** on chats whose reply finished while another chat was open, a "while you were away" toast when replies finished in the background, a live spinner per chat that is still generating, rename/delete, model picker, streaming chat, sanitized markdown, collapsible reasoning ("thinking"), and per-message token usage. Chats are named automatically from the first exchange (your own renames are never overwritten).
- **Workspace file tools (full OpenCode-style set):** the toolbar **Workspace** button attaches a folder to the active chat (a global default folder can be set in Settings → Appearance), which gives the model sandboxed tools: `list_files`, `read_file` (with line ranges), `read_many`, `search_files`, `find_definition`/`find_references`, `get_file_info`, `diff_files`, `write_file`, `edit_file` (exact-fragment replace), `apply_patch` (unified diff), `create_folder`, `delete_file`, `move_file`, `run_command` (allow-listed dev commands, no pipes/chaining, 60 s timeout), `git_status`/`git_diff`/`git_commit`, `memory_read`/`memory_save` (persistent `.lumen-memory.md` per workspace), `todo_write` (a live checklist panel in the UI) and `web_fetch` (per-domain approval, private/LAN hosts refused). All paths are confined to the workspace (`..`, absolute paths and symlink escapes are rejected); **every mutation shows a native approval dialog with a unified-diff preview**; a `LUMEN.md` in the workspace root is injected into the system prompt, and the first message of a chat carries the project tree. Before any change the old file is snapshotted into `.lumen-backup/` — the **Workspace activity** panel (clock icon) logs every operation and offers one-click **rollback**. A per-chat **read-only mode** (toolbar shield) disables all mutating tools. Tool output per reply is budget-capped (≈200 k chars) so a runaway loop cannot flood the context.
- **Chat productivity:** **Summarize** (toolbar sparkles) condenses a long chat and offers a fresh chat seeded with the summary; **export to HTML/PDF** (Settings → Data) renders the conversation as a styled standalone document; **prompt templates** with `{{input}}` placeholders (Settings → Personas → Prompt templates, composer's template button, or `/template N`); **slash commands** (`/model`, `/persona`, `/template`, `/clear`, `/summarize`, `/readonly`, `/help`); **voice input** (mic button, Web Speech API); live **token/cost counter** under the composer; **markdown preview** toggle for the draft.
- **Messages:** regenerate (non-destructive — the outgoing answer is archived, see *History*), **Continue** when the provider reports a `length` finish reason, edit-and-resend a user message (everything after it is truncated transactionally), per-message delete, copy, **copy as quote** (with model + date attribution), **read aloud** (text-to-speech), **bookmarks** (flag icon; a jump strip appears above the feed), long messages **collapse** with a "show full message" toggle, images open in a **lightbox** on click, and the streaming bubble shows an indeterminate **progress bar**. Day separators, code-copy buttons and finish-reason badges as before.
- **Composer:** **Enhance prompt** rewrites the draft with the selected model before you send it, **ArrowUp** recalls sent messages, text typed while a reply streams is **queued** and auto-sent (up to 10 per chat), plus **templates**, **slash commands**, **voice input**, **markdown preview** and a live **token/cost counter**.
- **Cost estimates:** providers carry per-model USD prices (per 1M tokens, editable via the provider's pricing map; sane defaults ship for the built-in model lists). Assistant messages show `≈$` next to their token counts, and Settings → Data & privacy shows the estimated lifetime cost alongside token totals. Models without a known price simply show tokens.
- **Branching:** the **Branch** action on any message forks the conversation into a new chat titled `<title> (branch)`, copying everything up to and including that message — variants and attachments included. From then on the two chats are fully independent. The toolbar links a branch back to its source and lists the forks of the active chat. Branches inherit the source chat's folder and workspace.
- **Personas & templates:** named presets (system prompt + color + optional temperature/provider/model overrides), managed in Settings → Personas and selected per-conversation from the composer; **prompt templates** live in the same tab and expand `{{input}}` into your draft.
- **Variants:** each regenerated answer keeps its predecessors; **History (n)** lists them with a preview and one click restores a previous answer in place.
- **Providers:** keys (with a saved-key indicator so you can leave the field blank to keep it), base URLs, model refresh/test, add/remove models, remove a custom provider, and a custom OpenAI-compatible endpoint. The seven cloud providers have pinned URLs; use a custom provider to point at anything else.
- **Appearance:** dark/light theme (the light theme is a warm "paper" palette, not a dark-theme inversion), **theme presets** (Default / Midnight / Sepia — full palettes for both dark and light), accent color, **three interface densities** (Comfortable / Default / Compact), **custom CSS themes** (load any .css file), **default workspace folder**, system prompt, temperature, top-p, response token limit and **reasoning effort** (Off / Low / Medium / High — maps to `reasoning_effort` for OpenAI o-series/gpt-5, `thinking.budget_tokens` for Claude 3.7+/4+, `thinkingBudget` for Gemini 2.5+, `reasoning.effort` for OpenRouter; "Provider default" changes nothing); system options (tray, autostart, notifications) and rebindable keyboard shortcuts. The toolbar also has **focus mode** (conversation only, Esc exits) and an **always-on-top** toggle. On Windows 11 the window chrome uses the **Mica material** (translucent titlebar/sidebar); Windows 10 keeps the solid theme colors.
- **Data & privacy:** local-storage details, cumulative token usage by model, **per-day statistics with cost bars** (Settings → Statistics), Markdown/JSON/**HTML/PDF**/**zip** chat export (zip = conversation.md + messages.json + attachment files), **database backup/restore** (backup copies the DB + attachments into a chosen folder; restore restarts the app and keeps a `.pre-restore` copy), "open data folder", and erase-all-conversations behind an inline confirmation. The same tab also has an **Updates** section (check now / restart & install).
- **Tabs & palette:** chats you open appear as **tabs** above the conversation (a dot marks the one still generating; closing the active tab moves to its neighbour); `Ctrl Tab` / `Ctrl Shift Tab` cycle them. `Ctrl P` opens a **command palette** with the common actions plus fuzzy chat jump.
- **Quick chat:** `Ctrl Shift Q` toggles a small always-on-top mini window (centered on the monitor under the cursor) that answers a one-off question using the provider/model of your most recent chat — Esc or clicking away hides it. The hotkey is rebindable like the others.
- **Compare mode:** the toolbar ⇄ button replays the conversation's last turn on a second provider/model and shows both answers side by side (the current chat's answer is reused, not re-billed).
- **Documents (RAG-lite):** the toolbar book button attaches up to 8 text/markdown/PDF documents (≤20 MB, text capped at 200k chars each) to a chat; per message the most relevant excerpts (keyword-ranked 1.8k-char chunks, ~8k budget) are injected into the system prompt, so answers can quote your files without a vector store.
- **MCP servers:** Settings → Personas registers up to 5 **Model Context Protocol** servers (stdio commands, e.g. `npx -y @modelcontextprotocol/server-filesystem .`). Their tools are exposed to every model namespaced as `mcp: <tool>`; a server that fails to start is skipped with a note instead of breaking the chat.
- **Sub-agents:** the model can call `spawn_subagent` to delegate an investigation to a bounded read-only helper (max 3 tool rounds, no writes/commands/approvals) that reports back a compact summary — keeping the main context clean.
- **Tool visibility & safety:** tool calls render as **cards** in the streaming bubble (name, argument hint, running/ok/declined/failed); a file mutation pops an **actionable toast with one-click rollback**; **watch_files** tells the model which workspace files changed on disk outside the app since its last answer; `sql_query` runs read-only SELECTs over workspace `.csv`/`.sqlite`/`.db` files.
- **Answers:** assistant messages carry a **👍/👎 rating** (persisted, click again to clear) and **mermaid** fenced blocks render as diagrams (lazy-loaded, strict security level, theme-aware; invalid diagrams stay code blocks). The composer autocompletes `@file` paths from the workspace.

## Keyboard
Shortcuts are rebindable in Settings → Appearance (a chord must include Ctrl or Alt); the defaults are:
- `Ctrl K` — new conversation
- `Ctrl ,` — open settings
- `Ctrl B` — toggle sidebar
- `Ctrl Shift Q` — toggle the quick-chat mini window (global, works when Lumen is in the tray)
- `Ctrl P` — command palette · `Ctrl Tab` / `Ctrl Shift Tab` — cycle open chat tabs
- `Enter` — send · `Shift Enter` — newline · `Ctrl/Cmd Enter` — send even during IME composition or from the message editor
- `Esc` — close the settings dialog / palette / quick chat, cancel the erase confirmation, cancel a hotkey capture, or clear/close the sidebar search

## Images / vision
Attach up to 4 images per message (PNG, JPEG, WebP or GIF, ≤10 MB each) via the attach button, paste, or drag-and-drop; an image-only message is valid. Bytes are stored as plain files under `userData/attachments/` (keeping them out of `lumen.sqlite`, which sql.js re-exports in full on every flush), with metadata in the database, and are served back to the sandboxed renderer through the CSP allow-listed `lumen-attachment://` protocol. Vision payloads are built per provider family: Anthropic image blocks, Gemini `inlineData` parts, and OpenAI-compatible `image_url` data URLs. Deleting a message, chat, edit-truncating, or wiping data removes the corresponding files. Edit-and-resend intentionally re-sends text only, and exports stay text-only.

## Tray and autostart
Settings → Appearance → System: "Keep running in the tray" hides the window on close instead of quitting (quit via the tray menu); "Launch at sign-in" registers the app with Windows via `app.setLoginItemSettings`.

## Current scope
Text chat, SSE streaming, **concurrent generation in several chats at once**, generation cancellation, a per-chat **message queue** while streaming, regenerate with variant history, continue-after-truncation, message editing, per-message delete, conversation branching with lineage navigation, **pinned chats, sidebar folders, tags and archive**, **filtered global search with jump-to-message**, the **full workspace toolset** (diff-previewed writes, edit/patch, command runner, git tools, snapshots with rollback, memory, todos, web fetch, read-only mode, **sql_query**, **watch_files**), **MCP tool servers**, read-only **sub-agents**, chat **summarization**, **HTML/PDF/zip export**, **voice input**, **prompt templates**, **slash commands**, **message bookmarks** and **answer ratings**, long-message collapse, **text-to-speech**, **lightbox**, **unread badges**, **chat tabs**, **command palette**, **quick-chat mini window**, **model compare mode**, **attached-document RAG**, **mermaid diagrams**, **tool-call cards** with **actionable rollback toasts**, `@file` autocomplete, **auto-updates**, **design refresh** (accent-driven design tokens, message bubbles, visible focus rings, slim themed scrollbars, unified motion, OS-style tabs, branded avatars, provider dots, richer empty states), **focus mode**, **always-on-top**, **custom CSS**, **compact mode**, per-day **usage statistics**, **backup/restore**, image attachments with per-provider vision payloads, personas, **Enhance prompt**, **prompt history recall** (ArrowUp), LLM-generated chat titles, tray mode and autostart, completion notifications, rebindable shortcuts, accent themes, token usage with **USD cost estimates**, day separators and per-block **code copy**, reasoning-model output, stream watchdog, bounded history, SQLite history, provider configuration, themes and exports are implemented. Reload-safe: generations that outlive a renderer reload are re-attached on startup instead of being orphaned.

Durability: conversation writes go through `BEGIN`/`COMMIT` transactions, are serialized atomically (temp file → `fsync` → rename) so a crash cannot leave a half-written database, and any write failure is surfaced through `data.health` rather than swallowed. A corrupt or 0-byte database is quarantined to `lumen.sqlite.corrupt-<timestamp>` and rebuilt with a warning naming the file; a database written by a newer schema version is refused instead of being overwritten. API keys are encrypted with `safeStorage` (Windows DPAPI) and a key that cannot be decrypted on the current account produces an actionable error instead of a silent auth failure. Local OpenAI-compatible servers (Ollama, LM Studio) work with no key at all.

Observability: the main process logs with a `[lumen]` prefix, catches `uncaughtException`/`unhandledRejection`, reports window load failures, and shows a dialog instead of dying silently if startup fails. DevTools and reload shortcuts are disabled in production builds only, so they stay available under `npm run dev`.

Not included yet: arbitrary JSON templates. Built-in model lists are suggestions; connection test refreshes models where supported.

## Known packaging gaps
These need decisions beyond code, so they are documented rather than changed:
- **asar is disabled on the CLI** (`--config.asar=false` in `dist:win`), which ships readable source in the packaged app. Enable asar (with `asarUnpack` for `node_modules/sql.js/dist/**` — the WASM loader resolves that path at runtime) once the loader paths are verified in a packaged build.
- **Auto-updates via GitHub Releases**: `package.json → build.publish` points at the (private) repo and electron-updater checks on startup and from Settings → Data → Updates. Because the repo is private, the check needs a `GH_TOKEN` environment variable with release read access; without it the app simply reports that no update info is available.
- The exe's own embedded icon stays stock Electron because `dist:win` passes `-c.win.signAndEditExecutable=false` (skips the rcedit step); the live window/taskbar icon is set via `BrowserWindow.icon` from `build/icon.ico`.
